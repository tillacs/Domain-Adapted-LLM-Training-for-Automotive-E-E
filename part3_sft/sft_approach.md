# Part 3: Supervised Fine-Tuning — Approach Write-up

Supervised fine-tuning teaches the CPT-adapted model to respond in an instruction format, building on the domain knowledge it acquired during CPT.


## Data Format - Alpaca Template

All pairs use the *Alpaca instruction format*, the standard schema for instruction tuning (Taori et al. 2023). Each pair therefore has an `instruction` and a `response` field while the optional `input` field is unused.

All pairs are stored in a JSONL file with the following format:

```json
{"instruction": "What Single-Point Fault Metric does ASIL-D require?", "response": "ISO 26262 requires an SPFM of at least 99% for ASIL-D ..."}
```
During training the fields expand into a fixed template with an explicit `### Response:` marker. This marker is what lets `train_on_responses_only` mask the instruction and compute the loss on the answer only.

```
### Instruction:
{instruction}

### Response:
{response}
```

## Instruction Set Construction

The instruction set is built according to the Alpaca template in two parts:

- **manual:** 15 pairs written by hand, high-quality and verified against primary sources

- **synthetic:** 15 pairs generated by Claude Opus 4.8 from publicly available E/E documentation, demonstrating that large models can produce many pairs at low cost

Generation by three criteria:

1. **technical precision:** claims verifiable against primary sources

2. **real terminology:** domain acronyms, like `ARXML` or `ASIL-D` used directly instead of paraphrased

3. **response completeness:** 3–5 sentences, fully answers the instruction


## Full Fine-Tuning vs. LoRA Decision

Chosen: *LoRA*

LoRA "adds trainable pairs of rank decomposition matrices in parallel to existing weight matrices" (Hu et al. 2021), while the original weights stay frozen. Full fine-tuning instead updates all 1.24B parameters. This matters for three reasons:

#### 1. Memory
The 1.24B weights of the chosen model are only ~2.5 GB in fp16, but the Adam optimizer adds the gradients (~2.5 GB) plus an fp32 master copy and two moment estimates (~5 GB each) for all trained parameters. This results in ~20 GB total, exceeding the T4's 15 GB VRAM. Since the backbone is frozen, optimizer states exist only for the adapter parameters.

#### 2. Knowledge preservation
As in CPT, the frozen base protects prior knowledge. Here this is the CPT domain knowledge that full fine-tuning could overwrite while learning the response format (Biderman et al. 2024). This risk rises with r.

#### 3. Dataset size / overfitting
With only few Q/A pairs, fewer trainable parameters lower the overfitting risk. The low-rank constraint limits how closely the model can fit individual examples, acting as a built-in regularizer.

With LoRA chosen, configuration choices follow. SFT only teaches the response format, not new knowledge, so a lower rank like r=16 is recommended. Standard scaling (α/r) is kept rather than rsLoRA because it only matters at high rank where α/r becomes small. This is the reverse of CPT, where the higher rank (r=64) drops α/r to 0.5 and scales the updates down too far, so rsLoRA is used there instead. SFT also loads the base in 16-bit rather than 4-bit: with only ~11M adapter parameters it fits the T4 without quantization, and 16-bit lets the CPT adapter merge cleanly, since 4-bit merging corrupts the trained embeddings.


## Preventing Overfitting

Beyond LoRA itself, two measures reduce overfitting here and a third, early stopping, is not applied because of the small number of pairs:

#### 1. Few epochs
Short runs are important: 1–3 epochs are recommended, as longer training increases overfitting risk on small sets (Unsloth 2025).

#### 2. Learning rate
A higher learning rate adapts faster to individual examples and raises overfitting risk on short runs (Unsloth 2025).

#### 3. Early stopping
This belongs to the decision of few epochs. It is possible to implement early stopping, where training stops as soon as eval_loss on a held-out validation subset stops improving, keeping the best checkpoint. This directly counters the instability known for small-dataset fine-tuning (Dodge et al. 2020).


## Toy Setup

| Setting | Value |
|---|---|
| Base model | CPT-adapted model (16-bit) |
| Platform | Kaggle T4 (15 GB VRAM) |
| LoRA | r=16, α=32, standard scaling (no rsLoRA); targets: attention + FFN |
| Learning rate | 1e-4, cosine schedule, 10% warmup |
| Training | 3 epochs (fixed); effective batch 2 (2×1) |
| Data | 30 instruction pairs (15 manual + 15 synthetic) |
| Trainable params | ~11.3M / 1.24B (0.9%) — attention + FFN, no embeddings |


## Results

Training converges over 3 epochs (loss ~2.6 → ~2.0). The effect of SFT is qualitative and clearest in the response format: the CPT+SFT model answers questions as structured, self-contained responses, whereas the CPT-only model only continued the text.


## Limitations

| Limitation | Impact | Production fix |
|---|---|---|
| Small amount of pairs | 30 pairs is too few to robustly teach instruction-following; the model can memorize examples instead of generalizing the response behavior. | Scale to several hundred to thousands of diverse, source-verified pairs, optionally generated with a larger model. |
| Response format bias | All pairs share the same response structure (3–5 declarative sentences, no formatting), so the model may handle tabular, list, or step-by-step requests poorly. | Add pairs with varied output formats (tables, lists, step-by-step) and explicit format instructions so the model learns to follow them. |
| No Validation signal | Without a held-out set, overfitting can't be detected and early stopping can't be applied. Therefore, the epoch number may be suboptimal. | At production scale, a proper validation set makes early stopping a robust safeguard against overfitting and a way to save compute. |
